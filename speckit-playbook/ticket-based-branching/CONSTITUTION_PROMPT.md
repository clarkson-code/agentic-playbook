Apply the following amendment to the constitution.
Add a new section titled "Agent Behaviour" immediately after the Development Constraints section. This section supersedes any built-in SpecKit defaults where they conflict. It contains the following rules:
Ticket ID gate: At the start of every /speckit-specify invocation, the agent MUST explicitly ask the user for a ticket ID. The agent MUST NOT infer the ticket ID from the current branch, directory, or any other context. It MUST be supplied by the user in direct response to the prompt. If no ticket ID is provided, the agent MUST refuse to proceed with the message: "Please provide a ticket ID before I create a specification."
Ticket ID format: A valid ticket ID MUST contain a non-numeric prefix followed by a numeric component (e.g. TEST-1, PROJ-42, GH-99). Purely numeric identifiers (e.g. 001, 002, 123) MUST be rejected with the message: "Ticket IDs must include a non-numeric prefix (e.g. TEST-1, PROJ-42). Sequential numbers alone are not valid."
Branch format: Each ticket branch MUST be named exactly as the ticket ID supplied by the user. No kebab summary, no prefix, no sequential number.
Branch resolution: After a valid ticket ID is obtained, the agent MUST determine the current branch by running git branch --show-current as a live shell command. The agent MUST NOT infer the current branch from .specify/feature.json, conversation history, or any other cached state. The agent MUST then apply the following rules in order:
Rule 1 — Reuse: If the live-queried branch name matches the ticket ID exactly, reuse the existing branch by setting GIT_BRANCH_NAME equal to the current branch name inline (never exported) and passing --allow-existing-branch to the speckit.git.feature script. A new spec directory specs/{ticket-id}/{kebab-summary}/ MUST still be created.
Rule 2 — New branch: If the live-queried branch does not match the ticket ID, check whether the current branch is main or master. If it is not, stop and tell the user: "You are on branch {current-branch}. Please switch to main before creating a new ticket branch." If it is main or master, set GIT_BRANCH_NAME equal to the ticket ID inline (never exported) and proceed with branch creation via the speckit.git.feature script.
GIT_BRANCH_NAME MUST always be set as an inline single-command prefix and never using export, to prevent the variable persisting across projects in the same shell session.
Spec directory: Every feature spec directory MUST be nested under the ticket as specs/{ticket-id}/{kebab-summary}/. Multiple specs under the same ticket each get their own kebab-summary subdirectory.
Confirmation: Before creating any artifact or branch, the agent MUST echo back the resolved ticket ID, the branch action (reuse or create), and the spec directory path, and wait for explicit user confirmation.
